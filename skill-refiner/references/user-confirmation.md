# Refiner 使用确认与问题恢复

本规则适用于通过 skill-refiner 创建、优化或验证目标 Skill 的工作流。

## 何时询问

1. **每条独立 create/run 工作流开始前确认一次**：包括该任务/目标的首次使用；用户已经明确授权该工作流或明确要求在其范围内自主执行时，直接按已有授权继续，不重复询问。每个 create 或 run 都是独立工作流；一次批准不能自动覆盖另一条工作流。创建流程内部按同一冻结计划启动的 refinement 子流程属于该 create 工作流，不重复询问。
2. **同一 run 的计划与继续执行**：如果用户批准的是完整 create/run 工作流，plan-only 与同一 run 的后续执行共用这次批准；只要冻结计划仍在确认的目标、输入、backend/model、写入范围和预算内，就自主继续。若用户只要求 plan-only，则停在计划结果。
3. **可恢复问题自主迭代**：控制器、Schema、计划或复核门出现可定位且可在授权范围内解决的问题时，保留错误和完整反馈，自主修复、运行相关检查并重新验证受影响的门禁；不得跳过门禁。恢复时复用校验通过的阶段和检查点，累计已用预算，不能通过新建运行清零。
4. **确实需要决策时询问**：业务目标存在无法合理推断的重大歧义、缺少无法自行取得的权限或配额、已批准的硬预算耗尽，或必须进行未授权的目标、输入、后端、外部副作用等实质变更时，停止并说明具体证据及选择。沉默不是批准。用户明确授权自主恢复或范围调整时，按该授权执行。

## 测试、演示与合成需求的自主决定

- 只有任务明确属于测试、演示或合成示例时，才按示例处理；不能仅凭名称含有 demo 就把真实业务降级为示例。主 Agent 对授权范围内可逆的默认值、样例数据和未规定的边界自主选择合理方案，不为这些非重大事项反复询问。未知能力若不属于用户要求，也可有依据地列为范围外；不凭关键词缺失排除真实要求的组合场景。
- 每项选择记录为**示例假设**，写明假设内容、适用范围、理由、相关需求与场景；作为独立标识的补充来源纳入分析、测试合同、开发与验收用例，并用实际测试证据逐项验证。用户原始需求文件和明确规则保持不变；假设不能标记为用户确认，也不能写成真实业务政策。
- 若已有运行因该事项停在 `needs_clarification`，保留原始输入、响应、状态及消耗；将示例假设作为独立补充源，按控制器支持的版本化检查点迁移/恢复合同重新冻结受影响输入，继承累计预算并重新验证受影响阶段。不得修改旧锁、重复计算已完成且仍有效的工作，或把旧分析和旧测试结论当作新输入的通过证据。
- 示例假设只约束该合成任务。真实业务中会实质改变结果、产生不可逆或外部影响、缺少必要授权的事项，以及用户已明确规定的事项，不得自行改写或用假设代替授权；无法合理确定时提出具体问题。来源不明或范围不明时按真实业务保守处理。
- 测试预期与假设要区分于测试实测结果。假设可以成为示例用例的预期来源，但必须有相应实际执行和独立验收证据，才能报告在该假设下通过；不得将示例通过推广为真实业务已确认或已验证。

## 自主修复范围

普通失败用例和可恢复的控制器、Schema、计划及复核缺陷，均应自主诊断、修复并回归，不在每个阶段或每轮修复前重复询问。每个用例仍须独立报告 PASS/FAIL/ERROR/NOT_RUN、断言期望值和实际值及证据。修订后完整重跑受影响的控制与门禁。预算、重试和停止条件须可见；同一问题无实质进展时停止并说明，不无界循环，不把新运行当作预算重置。

## 工作流开始确认

询问时一次说明：

- 目标 Skill、create/refine 模式、用户目标和输入路径/哈希。
- 计划生成与执行范围、子 Agent/逐例执行方式、候选产物位置和外部副作用（如不发布）。
- backend/model、完整工作流的时间/调用/评测/修复轮预算。
- 失败时自主修复和重新验收的方式，以及哪些无法自行解决的权限、业务决策或硬预算边界需要用户介入。

批准只适用于所述的一条有界工作流。若计划生成后发现目标、输入、后端、预算或副作用显著超出说明，先暂停并重新询问。

## 持久化批准记录

run 已创建时，将每次工作流开始或问题恢复的用户决定追加到 run 根目录的 approvals.jsonl，每行一个 JSON 对象，并按 schemas/v1/user-approval-record.schema.json 校验。记录 workflow_start 或 problem_recovery、输入哈希、backend/model、预算、写入范围、决定与时间；不要保存密钥或不必要的完整对话。首次批准先记在父 GoalExecutor artifact，创建 run 后关联到 run。批准记录不替代 stages.json 或逐例测试证据。
